# Тест-кейсы REST API JSONPlaceholder

**Базовый URL:** `https://jsonplaceholder.typicode.com`

Техники тест-дизайна: позитивное тестирование, негативное тестирование, граничные значения.

---

## TC-01. Получение существующего пользователя

| Поле | Значение |
| --- | --- |
| **ID** | TC-01 |
| **Заголовок** | Получение пользователя по валидному ID |
| **Тип** | Позитивный |
| **Техника** | Позитивное тестирование (happy path) |

**Предусловия:**
- Сервис JSONPlaceholder доступен.
- Пользователь с `id = 1` существует в системе.

**Шаги:**
1. Отправить `GET`-запрос на `/users/1`.
2. Получить HTTP-ответ и тело в формате JSON.

**Ожидаемый результат:**
- HTTP-статус `200 OK`.
- В теле ответа поле `id` равно `1`.
- В теле ответа поле `username` равно `"Bret"`.

## TC-02. Запрос несуществующего пользователя

| Поле | Значение |
| --- | --- |
| **ID** | TC-02 |
| **Заголовок** | Получение пользователя по несуществующему ID (граница диапазона) |
| **Тип** | Негативный / Граничное значение |
| **Техника** | Негативное тестирование, граничные значения (ID далеко за пределами существующего диапазона 1–10) |

**Предусловия:**
- Сервис JSONPlaceholder доступен.
- Пользователя с `id = 99999` в системе нет.

**Шаги:**
1. Отправить `GET`-запрос на `/users/99999`.
2. Получить HTTP-ответ.

**Ожидаемый результат:**
- HTTP-статус `404 Not Found`.
- Ресурс пользователя не возвращается как существующая сущность.

## TC-03. Создание нового поста

| Поле | Значение |
| --- | --- |
| **ID** | TC-03 |
| **Заголовок** | Создание поста с валидным JSON-телом |
| **Тип** | Позитивный |
| **Техника** | Позитивное тестирование (happy path) |

**Предусловия:**
- Сервис JSONPlaceholder доступен.
- Известен валидный `userId` (например, `1`).

**Шаги:**
1. Сформировать JSON-тело запроса:
   ```json
   {
     "title": "QA Automation Post",
     "body": "Created by automated test",
     "userId": 1
   }
   ```
2. Отправить `POST`-запрос на `/posts` с заголовком `Content-Type: application/json`.
3. Получить HTTP-ответ и тело в формате JSON.

**Ожидаемый результат:**
- HTTP-статус `201 Created`.
- В теле ответа поле `title` совпадает с отправленным заголовком `"QA Automation Post"`.
- В теле ответа присутствует идентификатор созданного поста (`id`).

## TC-04. Удаление только что созданного поста

| Поле | Значение |
| --- | --- |
| **ID** | TC-04 |
| **Заголовок** | Создание поста и удаление его по полученному ID |
| **Тип** | Позитивный |
| **Техника** | Позитивное тестирование (happy path), связанность шагов (создание → удаление) |

**Предусловия:**
- Сервис JSONPlaceholder доступен.
- Известен валидный `userId` (например, `1`).

**Шаги:**
1. Сформировать JSON-тело запроса:
   ```json
   {
     "title": "Post to delete",
     "body": "Created for TC-04 delete flow",
     "userId": 1
   }
   ```
2. Отправить `POST`-запрос на `/posts` с заголовком `Content-Type: application/json`.
3. Из тела ответа сохранить поле `id` созданного поста.
4. Отправить `DELETE`-запрос на `/posts/{id}` с этим идентификатором.
5. Получить HTTP-ответ на удаление.

**Ожидаемый результат:**
- Ответ на создание: HTTP-статус `201 Created`, в теле есть `id`.
- Ответ на удаление: HTTP-статус `200 OK`.
- Удаляется именно пост, созданный в этом тест-кейсе, а не фиксированный `/posts/1`.
